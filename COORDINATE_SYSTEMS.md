# Coordinate Systems

This document describes every coordinate system used in the hut2 project,
their sources of truth, and how they relate to each other.

## Overview

The project uses a chain of coordinate transformations from raw field
measurements to final SVG output. All building geometry lives in a single
primary frame (FC-based rotated coordinates). Other frames exist only as
intermediate steps or display transforms.

```
Field Survey (bearing/distance)
       │
       ▼
P3-Based Traverse (E/N feet, P3 = origin)
       │  subtract FC_IN_P3 = (18.5, 13.5)
       ▼
FC-Based Pre-Rotation (E/N feet, FC = origin)
       │  rotate CCW by arctan(14/85) ≈ 9.36°
       ▼
FC-Based Rotated  ◄── PRIMARY WORKING FRAME
       │               (all stored geometry lives here)
       │
       ├──► SVG Page Coordinates (floorplan, walls, survey path)
       ├──► Site Plan PDF Coordinates
       ├──► Span Graph Coordinates
       └──► Span Rotation Frame (temporary, for analysis)
```

## 1. Field Survey

- **Format:** Compass bearing (degrees CW from north) + distance (feet/inches)
- **Origin:** POB (Point of Beginning), the instrument station
- **Source:** `survey/rough_survey.txt`
- **Traverse:** POB → P2 → P3 → P4 → P5 → POB (CCW, 5 legs)

This is the ultimate physical measurement. Converted to Cartesian coordinates
by `shared/survey.py:compute_traverse()`.

## 2. P3-Based Traverse

- **Axes:** Easting (E) / Northing (N)
- **Origin:** P3 = (0, 0)
- **Units:** Feet
- **Positive:** E → east, N → north

The P3-based system is used only for the purpose of defining FC within the
P series. It is the first Cartesian representation of the field survey data,
existing as a transient intermediate inside `compute_traverse()`. No geometry
is stored in this frame. Its sole outputs are:

1. The FC-based `pts` dict (after subtracting `FC_IN_P3`).
2. The raw `_p3_trav` value, used exclusively by `make_svg_transform()` for
   SVG pixel calibration against a reference PDF.

The constant `FC_IN_P3 = (18.5, 13.5)` defines the building center as
18.5 ft east and 13.5 ft north of P3, providing the shift from this frame
to the FC-based frame.

## 3. FC-Based Rotated Coordinates (Primary Working Frame)

- **Axes:** Easting (E) / Northing (N), rotated from true north
- **Origin:** FC (building center) = (0, 0)
- **Units:** Feet
- **Positive:** E → right, N → up
- **Rotation:** CCW by `COORD_ROTATION = arctan(14/85) ≈ 9.36°` from P3-based frame
- **Traversal:** CW (F1→F2→...→F20→F1); interior on right side
- **Defined in:** `shared/survey.py`, `floorplan/geometry.py`

This is the frame in which all building geometry is stored and computed.
Every point in the project — F-series outline, W-series inner walls,
S/G-series shell boundaries, C-series arc centers, interior walls,
furniture, openings — lives in this coordinate system.

### Point series (all in this frame)

| Series | Inset from F | Meaning |
|--------|-------------|---------|
| F1–F20, F11a, F11b | 0" | Outline (outer face of building) |
| S1–S20, S11a, S11b | 2" (SHELL_THICKNESS) | Inner face of outer shell |
| G1–G20, G11a, G11b | 6" (SHELL_THICKNESS + AIR_GAP) | Outer face of inner shell |
| W1–W20, W11a, W11b | 8" (WALL_OUTER) | Interior wall face |
| C1, C5, ..., C19, C11a | — | Arc centers |

### Source of truth

The F-series outline is generated by a chain walk in
`floorplan/geometry.py:walk_outline_chain()`, starting at F2 bearing north
and following the `OUTLINE_CHAIN` recipe of line segments and arcs.
All other point series are derived from F by inset computation.

## 4. SVG Page Coordinates

- **Axes:** X (right), Y (down)
- **Origin:** Top-left corner of page
- **Units:** SVG points (1/72 inch)
- **Page size:** 792 × 612 points (US Letter landscape)
- **Scale:** ~11.66 SVG points per foot (calibrated)
- **Defined in:** `shared/svg.py:make_svg_transform()`

Transform from FC-based coordinates:
```
to_svg(e, n) = (px + e * scale, py - n * scale)
```

The Y-axis is inverted (N → up maps to SVG Y → down). The transform is
calibrated against known P3 and POB positions on a reference PDF.

## 5. Site Plan PDF Coordinates

- **Axes:** X (right), Y (down)
- **Origin:** Top-left of PDF page
- **Units:** PDF points (72/inch)
- **Scale:** 2.4 points/foot (1" = 30' survey scale)
- **Defined in:** `site/gen_site_plan.py`

A separate affine transform from FC-based coordinates, calibrated to match
a parcel survey PDF at 1:30 scale. Independent of the SVG calibration.

## 6. Span Analysis Frames

### Span graph coordinates
- **Axes:** Easting → X, span (feet) → Y
- **Origin:** Graph area bottom-left
- **Units:** SVG points (portrait: 612 × 792)
- **Defined in:** `span/gen_span.py`

Y is inverted from SVG convention so that larger span values appear higher
on the page.

### Span rotation frame (temporary)
- **Axes:** Rotated E/N
- **Origin:** Centroid of inner wall polygon
- **Units:** Feet
- **Rotation:** 0°–180° search range
- **Defined in:** `span/gen_span_minmax.py`, `span/gen_span_min.py`

Used only during span-vs-angle analysis to find the building orientation
that minimizes N-S span. Ephemeral — not stored.

## Conventions

### Bearings
Compass bearings measured CW from north: 0° = N, 90° = E, 180° = S, 270° = W.
Conversion: `dE = dist * sin(bearing)`, `dN = dist * cos(bearing)`.

### Traversal directions
- **Survey traverse** (P-series): CCW as viewed from above
- **Construction outline** (F-series): CW as viewed from above
- **Interior side:** Right of CW traversal direction

### Arc directions
The `direction` field in `ArcSeg` ("CW"/"CCW") refers to each arc's own
sweep, not the outline traversal. CW arcs = convex corners (inner radius
shrinks at inset); CCW arcs = concave corners (inner radius grows at inset).

### Normal vectors
- `left_norm(p1, p2)`: unit normal to the left of p1→p2 (exterior for CW traversal)
- `seg_vecs(p1, p2)`: returns `(along, inward)` unit vectors for CW outline
- Interior offset uses negated left normal: `offset(pt, left_norm, -wall_t)`

### Units
All coordinates in feet. Physical dimensions specified in inches, converted
via `/ 12.0`. SVG output in points (1/72 inch).
